Platform standards

FSI Evidence Observatory positioning

A standards-safe framework for source-linked mobility burden metrics, RAG review, and human accommodation decisions.

Architecture layers

FSI outputs and CSS cohort-comparison outputs should be reviewed as decision-support metrics. They can organize evidence and expose contradictions, but they do not diagnose pain, establish legal entitlement, or replace individualized review.

FSI stability

Dynamic burden instability using activity-specific movement features such as vertical shock, jerk, movement variability, peaks, and impact.

CSS similarity

Similarity to a stable mobility reference state, not merely similarity to an activity label.

PICE burden

Autonomic pain/exertion burden using HR, HR zones, HRV/RMSSD/SDNN, and activity-specific context where available.

FME efficiency

Functional mobility efficiency that treats distance and duration as capacity when paired with low burden.

Decision-support layer

Reviewer-safe synthesis that keeps metrics, sources, limits, source quality, missing data, review boundaries, and legal standards separate.

RAG observatory

Qdrant retrieval, optional Neo4j context, and local LLM answers used only with source metadata and review boundaries.

Structured Retrieval for Mobility Evidence

RAG language should preserve activity family, activity subtype, body coupling, physiologic burden, mechanical exposure, vehicle type, route context, duration, distance, audit status, and metric coverage.

Retrieval should keep HR, RMSSD, recovery context, HR per mile, distance per mean HR, ACC dynamic RMS, jerk RMS, shock spike rate, cumulative dynamic shock, vehicle type, and body coupling available as separate facets. It should not collapse them into a universal burden score without a defined normalization baseline.

Evidence-source roles

Sources should not be treated as interchangeable. Each stream supports a different kind of claim.

The current case-study Evidence Corpus on HandicapSkater.com keeps the historical WHOOP/Strava longitudinal layer distinct from the episodic Kubios / Polar H10 layer, then merges both through the FSI Evidence Observatory for public review. CSS remains the cohort-comparison layer; it enhances comparison without redefining FSI.

Kubios / Polar H10

Primary activity-specific source for HRV/RRI, accelerometer motion exposure, vertical impact, jerk, FSI biomechanics, and CSS cohort-comparison outputs.

WHOOP

Longitudinal physiology context for heart-rate patterns, strain, recovery, and overnight HRV. It should not be treated as activity-specific HRV by itself.

Strava

Functional capacity context for route completion, distance, duration, elevation, and repeated mobility performance. It is not pain evidence by itself.

Legal and case records

Accommodation context, source chronology, review history, and public/private boundary controls.

Architecture boundaries

The platform should preserve module boundaries so proprietary scoring, retrieval, orchestration, and public standards do not collapse into one unreviewable system.

fsi_css

Core scoring only: FSI, CSS, PICE, FME, feature profiles, source-neutral math, and testable metric contracts.

FSI Evidence Observatory retrieval

Indexing, loaders, chunking, retrieval, prompt assembly, local LLM integration, and source metadata.

FSI Evidence Observatory agents

Orchestration, CLI wrappers, report generation, API surfaces, and Evidence Observatory integration.

Court-safe terminology

The platform should help reviewers ask better questions, not overstate what any one metric can decide.

Use

source-linked evidence, decision-support metric, corroborates the broader record, presumptive/directional where sample size is small, activity-specific biomechanics, individualized review, and environment-specific analysis.

Avoid

diagnostic conclusions, outcome guarantees, universal access claims, agency endorsement, court endorsement, FDA-approved claims, and private invention-origin narrative.

Cross-domain use

The standards vocabulary can support biomechanics, transportation, rail/shared ride review, health records, finance, operations, and accessibility workflows when claims stay tied to source history and review context.
